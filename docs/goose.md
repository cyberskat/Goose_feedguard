# Goose — этап 6

Реализация языка [aardappel/goose](https://github.com/aardappel/goose), релиз
v2026.3. Синтаксис, арифметика и библиотечные API проверены по документации,
samples и stdlib именно установленного релиза, не по текущему master.
`goose version`: `goose runtime 4d3da949e563`.

## Сборка и запуск

```powershell
.\scripts\build_goose.ps1
.\goose\orderbook.exe --input data/normalized/events.bin
.\build\goose-debug\orderbook.exe --input data/normalized/events.bin
.\goose\orderbook.exe --self-test
python tests/test_goose.py
python tests/test_goose_boundaries.py
```

Build script использует `C:\tools\goose\goose-v2026.3-windows-x64\goose.exe`
и `C:\msys64\clang64\bin\clang.exe`; пути можно заменить параметрами
`-Goose` и `-Clang`. Кэш задаётся через GOOSE_HOME в `build/goose-home`.

Release: Goose `-O2`, сгенерированный C и runtime компилируются Clang 23.1.4
с `-O2`. Debug: Goose `--debug`, native `-O0 -g`, проверки переполнений и
приведений включены. Обычные проверки границ Goose сохраняются и в Release,
кроме доказанно лишних, которые удаляет компилятор.

Самостоятельный exe проверен из постороннего рабочего каталога, с абсолютным
путём к входу и PATH только `C:\Windows\System32`. Он не требует запуска
Goose-компилятора, C++ engine или чтения исходников при replay.

Без аргументов/с `--help` выводится справка. Неправильный формат, CRC, поля,
аргументы или недоступный файл приводят к ненулевому коду и диагностике stderr.
Результат выводится на stdout одним JSON, engine=`goose`; семантические поля
совпадают с C++. Файлы результата программа сама не перезаписывает.

`--trace` печатает JSON состояния после каждого события, включая архив и
текущую checksum истории. Сначала reader проверяет весь входной файл;
на проверенных повреждённых файлах частичная успешная трасса не выдаётся.
Трасса предназначена для проверки корректности, а не для измерения скорости.

## Структура

- `goose/model.goose`: фиксированные структуры, FNV, канонический порядок байтов.
- `goose/event_reader.goose`: собственный reader, CRC32 и проверка событий.
- `goose/book.goose`: сортированные уровни, бинарный поиск, snapshot/delta/reset,
  архив и JSON.
- `goose/self_tests.goose`: встроенные проверки ядра.
- `goose/orderbook.goose`: CLI и replay.

В kernel и reader нет вызовов готового C++ движка или стороннего parser.
Используется штатный os для файлов/вывода и штатные Goose std/binary.
CRC32, FNV, проверка событий и изменения стакана написаны на Goose.
Компиляция в C — штатный backend языка, не замена kernel на C++.

В Goose v2026.3 структура может иметь только одно растущее поле. Поэтому
метаданные книги фиксированы, а BID, ASK, архивные BID и ASK — четыре отдельных
`Level[>..<]`, передаваемых по ссылке. События и изменения хранятся в двух
непрерывных растущих массивах, как в C++.

Алгоритм: lower_bound, сдвиг диапазона при вставке/удалении. В delta удаления
выполняются до вставок. Жёсткого лимита вместимости книги в 50/64/4096 нет;
лимит 50 относится к snapshot, 4096 — к изменениям одной стороны в событии.
Встроенная проверка выращивает книгу до 4099 уровней и проверяет новый snapshot.

`valid_event` проверяет обе стороны до первого изменения книги и возвращает
false для неправильного события. Штатный replay уже получает проверенные данные,
но повторная проверка сохранена, как у C++. Ошибочные события не изменяют
текущие уровни, метаданные, часы или архив — это проверено непосредственно
через `apply_event`, отдельно от защиты reader.

Unsigned-арифметика Goose определена modulo 2^N, включая Debug. Поэтому
FNV-1a-64 реализован непосредственно, без float и отключения проверок.
Все цены/объёмы остаются i64, идентификаторы — u64. Формат и checksum:
[events-format.md](events-format.md), [order-book.md](order-book.md).

## Ограничения текущего этапа

Reader загружает файл целиком через штатный read_file; лимит 1 ГиБ проверяется
после загрузки. Затем декодируются события и уровни. Для очень большого
недоверенного файла это не предварительное ограничение выделенной памяти.
Ресурсные ошибки runtime могут завершить процесс; восстановление после OOM
не реализовано. Внешний вход не изменяет уже применённую книгу до полной
проверки файла.

Скорость Goose на этом этапе не измерялась. Сравнение с прежними C++-результатами
при -O3 было бы несогласованным: Goose сейчас собран при -O2. Следующий этап
должен выровнять native flags и отделить измерения от трасс/checksum истории.
