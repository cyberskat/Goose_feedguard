## Реализация

Две отсортированные vector<Level>, начальный резерв 64 уровня на сторону,
поиск через lower_bound. Вставка/удаление сдвигает непрерывный диапазон Level.
При превышении ёмкости память растёт геометрически; уровни не обрезаются.
Snapshot заменяет обе стороны, reset очищает их с сохранением ёмкости.

Оба движка вызывают одну функцию validate_book_event: одинаковые правила session,
timestamp, точности/шага, сортировки snapshot и отсутствия дубликатов. После
проверки vector рассчитывает окончательный размер обеих сторон и резервирует
память до первого изменения содержимого. В delta сначала выполняются удаления,
затем вставки/обновления: промежуточный размер не превышает max(старый, итоговый).
Level имеет небросающие copy/move операции, поэтому после успешного reserve
добавочных аллокаций в commit нет. При ошибке второго reserve первая сторона
может получить новую ёмкость, но её содержимое и метаданные не меняются.

Полного копирования стакана на каждую delta нет. Архив достоверного состояния
сохраняется перед reset по тем же правилам, что и у map.

## Корректность

- 38/38 тестов в каждом из четырёх профилей GCC/Clang, Debug/Release.
- Базовые проверки стакана стали общими template-тестами для map и vector.
- В стресс-тесте 100000 событий каждый шаг сравнивается между map, vector
  и независимой моделью на vector с линейным поиском; checksum обоих движков
  сравниваются после каждого события.
- Проверен рост до 4096 уровней на сторону, переход через эту ёмкость,
  смешанные вставки/удаления и сохранение резерва после reset.
- Все восемь реальных replay выдали одинаковые семантические JSON-результаты.
- Отдельная verify_engines сравнивает оба стакана, архив, best quotes, spread
  и checksum после каждого события реального файла до начала замера.
- Независимый Python replay подтвердил результат vector по исходному JSONL.

## Предварительный core-only эксперимент

```powershell
python benchmark/core_compare.py --runs 10 --repeat 50
```

Runner требует Clang Release, один прогрев каждого движка и минимум 10
измерений. Порядок map/vector чередуется. По умолчанию output —
`results/stage5-preliminary`; существующий каталог не перезаписывается.
Для повторения задайте новое имя через `--output`.

Каждый процесс заранее читает events.bin, сравнивает движки по каждому событию
и создаёт 50 свежих книг. Таймер охватывает только цикл apply по этим книгам.
В apply входят общая валидация, изменение уровней, snapshot/reset и архивирование.
Подготовка/уничтожение книг, file I/O, полные checksum истории, JSON и проверки
результата выполняются вне таймера. После замера состояние и архив каждой
из 50 книг сравниваются с проверенным результатом; проверяется текущая checksum.

500100 записей на прогон — это 50 повторений одного файла из 10002 записей
(10000 рыночных + 2 reset), а не 500100 уникальных рыночных событий.
Каждое повторение использует свежую книгу, поэтому steady_clock/session
не сбрасываются искусственно внутри рабочей книги.

Файлы результата:

- `core_results.csv`: 20 измерительных строк, время, events/sec, среднее ns/event,
  текущая и last_valid checksum, отдельно подтверждённая checksum истории.
- `raw_runs.json`: полные ответы измерительных процессов.
- `environment.json`: CPU, версии, фактические команды компиляции, флаги,
  SHA-256 входа/exe/исходников, порядок прогонов, состояние Git.
- `summary.md`: сводка, рассчитанная из сохранённых измерений.

### Измерено 2026-10-27

CPU: 12th Gen Intel Core i7-12650H. Clang 23.1.4, `-O3 -DNDEBUG`, C++20.
Оба движка находятся в одном exe и собраны с одинаковыми флагами.

| Движок | Медиана events/sec | Медиана среднего ns/event по прогонам |
|---|---:|---:|
| cpp_map | 2075224 | 481.88 |
| cpp_vector | 2666295 | 375.06 |

Отношение медианных throughput vector/map: 1.285x, около +28.5%.
Это не p50/p99 отдельных операций: ns/event получено делением времени пакета
на число записей. Отдельные latency percentiles и peak RAM пока не измерялись.
Фоновые приложения, частота CPU и привязка к ядру автоматически не контролировались.

В Git пока нет commit; environment фиксирует git_commit=null, dirty=true
и SHA-256 рабочих исходников вместо выдуманного идентификатора.
Полный бенчмарк трёх движков и согласование флагов C++/Goose — следующие этапы.
Текущие результаты C++ с -O3 нельзя напрямую сравнивать с Goose, собранным с -O2.
