# Collector — этап 2

Публичный mainnet `wss://stream.bybit.com/v5/public/linear`,
`orderbook.50.BTCUSDT`. API-ключи не нужны.

```powershell
$env:PATH = 'C:\msys64\clang64\bin;' + $env:PATH
.\build\clang-release\collector.exe --count 10000 --output data/raw/btcusdt-new.jsonl --timeout 600
python scripts/validate_capture.py data/raw/btcusdt-new.jsonl --expected 10000
```

`--count` считает только валидные snapshot/delta после первого snapshot
текущей сессии. Служебные subscribe/pong сохраняются отдельно.
`--timeout` — общий лимит в секундах (1–86400); код выхода 2 означает timeout,
130 — Ctrl+C/SIGTERM, 1 — ошибку, 0 — достижение count.
Без аргументов программа показывает справку и не подключается.
Выходной файл создаётся эксклюзивно: существующий файл не перезаписывается.
Для повторного запуска укажите новое имя.

TLS проверяет цепочку сертификатов и hostname, передаёт SNI,
допускает TLS >= 1.2. В MSYS2 используется CA bundle своего toolchain;
`--ca-file PEM` позволяет явно задать доверенные сертификаты.
TLS-проверки не отключаются.
Группы согласования ключей: X25519/P-256 (отдельно согласованы пользователем).

## Формат JSONL, schema 1

Каждая строка содержит `schema`, `session`, `kind`, `recv_utc_ns`.
Для входящих сообщений также записываются `recv_steady_ns`, `accepted`, `raw`.
`raw` — исходный JSON-объект, без преобразования десятичных строк в числа.
Физические CR/LF в JSON whitespace удаляются, чтобы сохранить одну строку
на запись; экранированные символы внутри строк не меняются.

Виды записей: `session_start`, `snapshot`, `delta`, `control`, `invalid`,
`disconnect`, `collector_stop`. Служебные события используют `detail`.
Повреждённый вход сохраняется в диагностическом `detail`, после чего
сессия разрывается и требуется новый snapshot. Не-ASCII диагностические
байты представлены escape-последовательностями; `raw` валидных сообщений
сохраняется в исходной UTF-8 кодировке.

Смена `session` и `disconnect` являются границами достоверности стакана.
После reconnect delta до snapshot не принимаются.
`u=1` допустим только для snapshot. `seq` не проверяется на шаг +1.
Точная нормализация decimal/int64 и масштабы инструмента относятся к этапу 3.

## Поведение соединения

- JSON ping каждые 20 секунд, websocket control ping/pong обслуживает Beast.
- Подключение/ожидание snapshot ограничены 30 секундами, TCP/TLS — 15 секундами.
- Отсутствие рыночных сообщений 30 секунд вызывает новое подключение.
- Backoff 1, 2, 4, 8, 16, 30 секунд; после получения данных счётчик сбрасывается.
- Ctrl+C и общий timeout закрывают WebSocket; принудительное закрытие сокета
  после трёх секунд ожидания гарантирует завершение close-handshake.

## Уменьшение накладных расходов C++

Один io_context и поток: нет блокировок между сетевыми callbacks.
Переиспользуются flat_buffer с начальным резервом 64 КиБ, simdjson parser,
строка журнала и stdio-буфер 1 МиБ. Числовые timestamp кодируются через
`to_chars` без промежуточных строк. JSON не сериализуется повторно.
Timestamp ставится до парсинга и записи. Watchdog не требует cancel/async_wait
для каждого рыночного события. TCP_NODELAY включён.

Запись буферизована, но выполняется в сетевом потоке: медленный диск может
задержать получение следующих сообщений. Это не hard real-time система.
Принудительное завершение процесса может потерять ещё не сброшенный буфер.
Отдельный writer-thread или lock-free очередь пока не добавлялись.
Измеренного ускорения и сравнения языков на этом этапе нет.

  Первые пять попыток завершились ошибками TLS, шестая получила данные.
  Программа завершилась с кодом 0. Независимый validator прошёл.

  `0dda1ec383742b16c5a203d391aff4d9bc87737fa133782ea6d18fd331093797`.
