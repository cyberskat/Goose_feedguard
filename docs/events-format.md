# FeedGuard events.bin, версия 1

Все целые little-endian, без неявного padding. `i64` — знаковое 64-битное
число в дополнительном коде. Файл не является дампом C++ struct.
MVP закреплён за `linear`, `BTCUSDT`, `orderbook.50.BTCUSDT`.

## Заголовок — 128 байт

| Смещение | Тип / размер | Поле |
|---|---|---|
| 0 | 8 bytes | ASCII `BFGDEVT1` |
| 8 | u32 | версия, 1 |
| 12 | u32 | размер заголовка, 128 |
| 16 | u32 | десятичная степень цены, 0–18 |
| 20 | u32 | десятичная степень количества, 0–18 |
| 24 | i64 | tickSize в целых единицах цены, >0 |
| 32 | i64 | qtyStep в целых единицах количества, >0 |
| 40 | u64 | число записей, включая reset |
| 48 | u64 | число рыночных snapshot/delta |
| 56 | u64 | размер payload в байтах |
| 64 | u32 | CRC32 всего payload |
| 68 | u32 | CRC32 заголовка с нулями в байтах 68–71 |
| 72 | 16 bytes | `BTCUSDT`, остаток заполнен нулями |
| 88 | 8 bytes | `linear`, остаток заполнен нулями |
| 96 | 32 bytes | SHA-256 точных байтов исходного REST metadata JSON |

CRC32: IEEE/ISO-HDLC, reflected polynomial `0xedb88320`, начальное значение
`0xffffffff`, итоговый XOR `0xffffffff`. Для `123456789`: `cbf43926`.
CRC обнаруживает случайное повреждение; это не криптографическая подпись.
SHA-256 связывает файл с сохранёнными metadata; reader без metadata-файла
не подтверждает, что параметры были получены именно от биржи.

## Запись — 72 байта + уровни

| Смещение внутри записи | Тип / размер | Поле |
|---|---|---|
| 0 | u32 | полный размер записи |
| 4 | u8 | тип: snapshot=1, delta=2, reset=3 |
| 5 | 3 bytes | резерв, строго нули |
| 8 | u64 | session, >0 |
| 16 | u64 | update ID `u` |
| 24 | u64 | cross sequence `seq` |
| 32 | u64 | `ts`, биржевое время публикации, мс |
| 40 | u64 | `cts`, время matching engine, мс; 0, если отсутствует |
| 48 | i64 | локальное время UTC получения, нс от Unix epoch |
| 56 | i64 | локальное steady_clock получения, нс; только для интервалов |
| 64 | u32 | количество изменений BID |
| 68 | u32 | количество изменений ASK |
| 72 | 16 × (BID+ASK) | сначала BID, затем ASK |

Один уровень: `price: i64`, затем `quantity: i64`. Цена положительна,
количество неотрицательно. Ноль количества допустим только в delta и означает
удаление. Значения кратны соответствующему шагу инструмента.
Дубликаты цены внутри одной стороны одного события запрещены.
Snapshot: не более 50 уровней на сторону, BID строго убывают, ASK возрастают.
Delta: порядок изменений сохраняется; лимит reader — 4096 изменений на сторону.
Пустые стороны допустимы.

Общий размер записи точно `72 + 16 * (bid_count + ask_count)`.
В конце файла нет trailer или дополнительных байтов. Максимальный размер
файла в текущем reader — 1 ГиБ. Все длины проверяются до доступа к массивам.

## Масштабы и точность

`целое = исходное значение × 10^decimals`. Значения не проходят через double.
Степень получается из tickSize/qtyStep после удаления незначащих дробных нулей.
Например, tickSize `0.10` даёт decimals=1 и целый шаг 1;
qtyStep `0.001` даёт decimals=3 и шаг 1.
Синтетический tickSize `0.50` даёт decimals=1 и шаг 5.

`80631.90` при decimals=1 превращается в 806319. Дополнительные дробные
нули разрешены, отбрасывание ненулевой цифры запрещено. Экспоненты, пробелы,
`NaN`, знак `+`, начальная/конечная точка запрещены. Проверяется int64 overflow,
включая крайние значения в общем decimal parser. Отрицательные цены и объёмы
рыночных сообщений запрещены.

## Границы сессий

Каждый `session_start` и `disconnect` исходного журнала становится reset.
Reset содержит только session и положительный receive_utc_ns; остальные поля
заголовка записи и количества уровней равны нулю. Session не уменьшается;
переход к новой session допустим только через reset.
После reset нельзя применять delta до нового snapshot.
`u=1` разрешён только для snapshot; seq может увеличиваться больше чем на 1.
`receive_steady_ns` рыночных событий не уменьшается в рамках всего файла;
UTC может корректироваться системными часами.

Конец нормального захвата также содержит disconnect/reset: после него стакан
недостоверен. Будущий engine должен отдельно сохранять последнее достоверное
состояние и/или контрольную сумму истории: одна checksum пустого стакана после
финального reset недостаточна для сравнения реализаций.

## Представление в памяти C++

`EventData.events` содержит дескрипторы, `EventData.levels` — единый массив
всех изменений. `first_level`, bid_count и ask_count задают непрерывные диапазоны.
`bids()` и `asks()` предназначены для уже проверенного EventData.
Отдельных vector на каждое событие нет. Подготовка/проверка reader выполняется
до будущего core-only измерения стакана.
